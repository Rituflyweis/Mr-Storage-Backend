Internal Communication · API + Real-Time Layer

Backend Integration Guide

Everything the frontend needs to wire up Direct and Group chat plus Notifications for internal staff — every REST endpoint, the socket connection, rooms, and every event the server emits or listens for.

Base URL {baseUrl}/api Socket namespace /admin Transport Socket.IO v4 Auth JWT access token Scope Admin · Sales · Plant · Construction · Account

01Overview

Two systems live under one auth model: Notifications (system-wide event alerts, REST-only for now) and Internal Communication (Direct + Group chat, REST + real-time sockets). Chat has two write paths — REST and socket — that stay in sync. A message sent either way is persisted the same way and broadcast over the socket to every connected participant, so the frontend can pick whichever path fits the moment: REST for the initial send-with-attachment flow, sockets for instant typing and delivery.

All internal chat traffic — direct messages, group messages, typing, read receipts, membership changes — flows through the single /admin namespace. There is no separate namespace per chat type. Notifications do not currently push over the socket — poll /notifications/unread-count or refetch the list on a relevant screen event.

02Frontend connection setup

Same access token drives both REST calls and the socket handshake — log in once, use it everywhere.

Environment

VariableExample
API_BASE_URLhttps://api.mrstorage.dev/api
SOCKET_URLhttps://api.mrstorage.dev (namespace /admin appended by the client)

1 — Authenticate

const { data } = await axios.post(`${API_BASE_URL}/auth/login`, {
  email: "user@mrstorage.dev",
  password: "••••••••",
});
const { accessToken, refreshToken } = data.data;
// accessToken expires in 15 min — POST /auth/refresh with refreshToken to renew

2 — REST calls

const api = axios.create({
  baseURL: API_BASE_URL,
  headers: { Authorization: `Bearer ${accessToken}` },
});

3 — Socket connection

import { io } from "socket.io-client";

const socket = io(`${SOCKET_URL}/admin`, {
  auth: { token: accessToken },
  transports: ["websocket"],
});

Full response envelope for every REST endpoint below:

{ "success": true, "message": "...", "data": { … } }
// errors: { "success": false, "message": "...", "errors": null | [...] }

03Direct & group chat endpoints

All under {baseUrl}/api/team-chat. Header Authorization: Bearer {accessToken} required on every call.

Direct chat

GET/team-chat/users?search=List / search staff to start a conversation
GET/team-chat/conversationsCombined direct + group list, sorted by recency
GET/team-chat/unread-countUnread badge (direct + group + total)
GET/team-chat/direct/:userId/messagesHistory, paginated — auto-marks read
POST/team-chat/direct/:userId/messagesSend a message (content and/or attachments)

Group chat

POST/team-chat/groupsCreate a group with members
GET/team-chat/groups/:groupIdDetail + populated member list
PUT/team-chat/groups/:groupId/membersAdd / remove members — admin-only
GET/team-chat/groups/:groupId/messagesHistory, paginated — auto-marks read
POST/team-chat/groups/:groupId/messagesSend a message (content and/or attachments)

Request / response examples

// POST /team-chat/direct/:userId/messages
{ "content": "Delivery is staged, dispatching at 3pm.", "attachments": [] }

// → 201, data.message
{
  "_id": "66f0c1...", "channelType": "direct",
  "directKey": "66e1a2_66f0c1", "participants": ["66e1a2...", "66f0c1..."],
  "senderId": "66e1a2...", "senderName": "Aisha Khan", "senderRole": "plant",
  "content": "Delivery is staged, dispatching at 3pm.", "attachments": [],
  "readBy": ["66e1a2..."], "createdAt": "2026-08-21T14:04:32.714Z"
}

// POST /team-chat/groups
{ "name": "Project Alpha Team", "memberIds": ["66f0c1...", "66f0c2..."] }

// PUT /team-chat/groups/:groupId/members
{ "addMemberIds": ["66f0c3..."], "removeMemberIds": ["66f0c2..."] }
Message send requires content or at least one attachments entry — never both empty. Attachments: max 10 per message, each needs a non-empty url, or the request returns 400.

05Attachment upload

Chat attachments reuse the existing presigned-URL flow — the socket/REST message events carry only the resulting file URL, never file bytes.

POST/upload/presigned-urlGet a signed S3 PUT URL
// 1. Request a signed URL
const { data } = await api.post("/upload/presigned-url", {
  fileName: "site-photo.jpg", fileType: "image/jpeg", folder: "chat-attachments",
});
const { uploadUrl, fileUrl } = data.data;

// 2. PUT the file directly to S3
await axios.put(uploadUrl, fileBuffer, { headers: { "Content-Type": "image/jpeg" } });

// 3. Send the message referencing fileUrl
await api.post(`/team-chat/direct/${userId}/messages`, {
  attachments: [{ url: fileUrl, name: "site-photo.jpg", type: "image/jpeg" }],
});

06Connect & authenticate (socket detail)

Open one socket per session against the /admin namespace and pass the same JWT access token used for REST calls in the handshake auth payload.

import { io } from "socket.io-client";

const socket = io("https://api.mrstorage.dev/admin", {
  auth: { token: accessToken },
  transports: ["websocket"],
});

socket.on("connect", () => {
  // Server auto-joins this socket to room `user:{yourUserId}`
  // — every direct-message notice and group-membership event lands here.
});

socket.on("connect_error", (err) => {
  // "Authentication required" — no token sent
  // "Invalid token"          — expired / malformed token, refresh and retry
});

On connect the server automatically:

  • Joins the socket to its personal room, user:{userId} — this is where DM notices and group-membership pushes are delivered, independent of which chat room the client has joined.
  • Joins admin_room additionally if the connecting user's role is admin.

No chat history is replayed on connect — fetch it via GET /api/team-chat/direct/:userId/messages or GET /api/team-chat/groups/:groupId/messages, then let the socket carry new messages from that point on.

07Rooms

A conversation only receives live events once the client explicitly joins its room with join_team_channel. Room names are derived server-side — the client never constructs them.

Channel typeRoom nameWho's in it
directteam_direct:{sortedUserIdA_userIdB}Both participants, once each has joined
groupteam_group:{groupId}Group members who have joined; membership is checked server-side on join
personaluser:{userId}Auto-joined on connect — carries DM notices, group notices, and membership-change pushes regardless of which room is open
The direct-room key is order-independent — joining a conversation with user B from user A's socket and joining with user A from B's socket land in the same room.

08Client → Server events

Emitted by the client to control which rooms it's listening on and to send messages.

channelId must always be a real Mongo ObjectId — either the other user's _id for direct, or the group's _id (from POST /team-chat/groups) for group. Never send a static string like "sales_team" or a department name as channelId — that belonged to the old department-chat system, not this one. There is no "department" channel type in this API; the only valid values for channelType are "direct" and "group".
emitjoin_team_channel

Joins the room for a direct or group conversation. Call this when a chat screen opens.

socket.emit("join_team_channel", {
  channelType: "direct",  // "direct" | "group" — nothing else
  channelId:   "66f0c1...",  // the other user's Mongo _id, or the group's Mongo _id
});

For group, the server verifies channelId is a valid ObjectId and that the connecting user is still a member before allowing the join. Either check failing is a silent no-op on join_team_channel — you won't get an event back, so confirm the join worked by checking that new_team_message events for that room actually arrive, not by assuming success.

emitleave_team_channel

Leaves a room. Call this when a chat screen closes, using the same payload shape as join_team_channel.

emitteam_typing_start / team_typing_stop

Broadcasts a typing indicator to everyone else in the room (the sender does not receive their own event back).

socket.emit("team_typing_start", { channelType: "group", channelId: groupId });
// other members receive → "team_typing" { isTyping: true, name: "Aisha Khan" }
emitteam_message

Sends a message into a direct or group conversation. Text, attachments, or both — at least one is required.

socket.emit("team_message", {
  channelType:  "direct",          // "direct" | "group"
  channelId:    "66f0c1...",
  content:      "Delivery is staged, dispatching at 3pm.",
  attachments:  [                        // optional, max 10
    { url: "https://…s3…/chat-attachments/photo.jpg", name: "site-photo.jpg", type: "image/jpeg" }
  ],
});

Upload attachments first via POST /api/upload/presigned-url, PUT the file to the returned S3 URL, then reference the resulting fileUrl here — the socket event carries only the URL, never the file bytes.

Unlike join_team_channel, an invalid channelId or a group you're not a member of on this event does emit team_chat_error back to you — listen for it and surface it, don't retry blindly.

09Server → Client events

Emitted by the server. Bind these once per socket connection, not per room — the payload tells you which conversation each event belongs to.

onnew_team_message

Fires to everyone in the room whenever a message is created — whether it came in over this event or over the REST send endpoint. This is the single source of truth for rendering new messages.

socket.on("new_team_message", (message) => {
  // {
  //   _id, channelType, groupId, directKey, participants,
  //   senderId, senderName, senderRole,
  //   content, attachments, readBy,
  //   createdAt, updatedAt
  // }
});
onnew_team_dm_notice

Delivered to the recipient's personal room (user:{id}) on every direct message — fires even if they haven't joined that direct room yet, so it's the right hook for a global "new DM" badge or toast.

socket.on("new_team_dm_notice", ({ fromUserId, fromName, content }) => { /* … */ });
onnew_team_group_message_notice

Same idea as the DM notice, for group messages — delivered to every other member's personal room, independent of whether they have the group open.

socket.on("new_team_group_message_notice", ({ groupId, fromName, content }) => { /* … */ });
onteam_messages_read

Fires to the room when a participant fetches messages via REST — the server marks everything unread-by-them as read and broadcasts this so the sender's UI can flip single-tick to double-tick in real time.

socket.on("team_messages_read", ({ by, channelType, channelId }) => { /* … */ });
ongroup_members_updated

Broadcast to the group's room whenever an admin adds or removes members via PUT /api/team-chat/groups/:groupId/members. A member who was just removed will have left the room server-side and won't receive this — handle their case client-side via a 403 on their next action, or a REST re-check.

socket.on("group_members_updated", ({ groupId, members }) => { /* members: full populated array */ });
onnew_team_group

Sent to a user's personal room when they're added to a group — either at creation or via a later member update. Use it to insert the new group into the conversation list without a refetch.

socket.on("new_team_group", ({ group }) => { /* full group document */ });
onteam_chat_error

Fires back to the sending socket only, when a team_message emit fails server-side (e.g. sender is no longer a group member).

socket.on("team_chat_error", ({ message }) => { /* show inline, do not retry blindly */ });

10REST vs. socket writes

Both paths write the same document and trigger the same new_team_message broadcast — pick based on what the moment needs.

11End-to-end flow — opening a group chat

Connect once

Open the socket on app load / login, authenticated with the current access token. Keep it alive across screens.

Load history

GET /api/team-chat/groups/:groupId/messages — this also marks unread messages as read and triggers team_messages_read to the room.

Join the room

socket.emit("join_team_channel", { channelType: "group", channelId }) — do this on screen focus.

Listen

Bind new_team_message, team_typing, and group_members_updated for this session.

Send

socket.emit("team_message", …) for quick sends, or the REST endpoint when attaching files.

Leave on unmount

socket.emit("leave_team_channel", …) when the screen closes — the socket itself stays connected for other rooms and DM notices.

12Error handling

  • Connection refused — connect_error fires with "Authentication required" (no token) or "Invalid token" (expired/malformed). Refresh the access token and reconnect; do not retry with the same token.
  • Silent no-op on join — joining a group room you're not a member of does nothing and emits nothing back. If a client expects to be in a group but never receives room traffic, re-fetch GET /team-chat/groups/:groupId to confirm membership rather than assuming a dropped connection.
  • Message rejected — team_chat_error arrives only on the sending socket, never broadcast. Typical cause: sender was removed from the group between opening the screen and sending.
Every event above was exercised against live socket connections between multiple concurrent users — direct and group sends, read receipts, and membership-change broadcasts — before this was written up.
